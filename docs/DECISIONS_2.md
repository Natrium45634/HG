# Архитектурные решения — часть 2 (расширение)

Документ фиксирует решения по второй части ТЗ («расширение тактической
игры»). Нумерация продолжает [DECISIONS.md](DECISIONS.md). Все числа —
значения по умолчанию, настраиваемые в редакторе (правила, определения
объектов), если не сказано иное.

## 18. Шаблоны карт

* Новая категория контента **«Шаблон карты»** (`map_templates/<id>.json`,
  вид `map_template`). Поля: ID, версия, название, описание, категория
  (группа библиотеки), теги, назначение, флаг «встроенный», набор
  сохраняемых частей и сами данные (клетки, метки, маршруты, правила).
* Сохраняемые части (флаги): форма и размер — всегда; типы местности;
  высоты; препятствия (клетки, местность которых — препятствие);
  точки появления (метки `PlayerStart/EnemySpawn/NeutralSpawn`); цели
  (метки `Objective/Exit/Trigger`); маршруты; прочие настройки (правила
  карты, переопределения клеток, стартовые эффекты).
* Не сохранённые части при создании карты заполняются нейтрально: пол по
  умолчанию (`floor`), высота 0, без меток.
* Встроенные шаблоны (данные + генератор в коде для восстановления):

  | ID | Размер / форма | Назначение |
  |---|---|---|
  | `standard_10x8` | 10 столбцов × 8 рядов (прямоугольник odd-r) | стандартная карта, **первый в списке** |
  | `small_arena` | шестиугольник радиуса 3 (37 клеток) | короткие стычки |
  | `wide_16x8` | 16 × 8 | фланговые манёвры |
  | `defense_12x8` | 12 × 8, коридор, вход справа, защищаемая зона слева, маршрут | оборона |
  | `boss_arena` | шестиугольник радиуса 5, приподнятое кольцо и центр | бой с боссом |
  | `empty` | 0 клеток | пустая карта, гексы добавляются кистью |

  «Пользовательский шаблон» — это (а) шаблоны, сохранённые
  администратором из своих карт (группа «Пользовательские»), и (б)
  генератор произвольного размера/формы в окне создания карты (ширина,
  высота, форма: прямоугольник, ромб, шестиугольник).
* 10 × 8 — стандарт, а не ограничение: размеры ограничены только
  `Limits.MaxMapCells`.
* Карта **копирует** данные шаблона и хранит происхождение
  (`templateId`, `templateVersion`). Изменение шаблона карты не меняет.
  Кнопка «Обновить карты из шаблона» показывает список карт с более
  старой версией шаблона и после явного подтверждения переносит в
  выбранные карты сохраняемые части шаблона.
* «Восстановить встроенные» пересоздаёт встроенные шаблоны из генератора
  (с подтверждением, старые версии попадают в историю).

## 19. Размер гексов и камера

* Радиус гекса в мире фиксирован (1,0); визуальный размер на экране
  задаёт камера. Масштаб подбирается автоматически: расстояние камеры
  вычисляется так, чтобы ограничивающий объём карты (с учётом высот и
  стен) при текущем наклоне, повороте и FOV проецировался в **рабочую
  область** — экран за вычетом панелей интерфейса (верхняя строка,
  панель действий, боковые панели).
* Расчёт — чистая функция ядра `CameraFit` (без Godot), поэтому
  проверяется тестами для 1280×720, 1920×1080, 2560×1440, 3840×2160 и
  2560×1080. Критерий: карта 10 × 8 целиком внутри рабочей области
  1920×1080, ширина гекса на экране не меньше 64 px (удобно попадать
  мышью) и не больше 160 px.
* Кнопки: «Вписать карту» (`V`; `F` уже занята атакой), «Стандартный масштаб» (`Ctrl+0`) —
  масштаб, при котором вписывается карта 10 × 8; колесо мыши — плавный
  зум, перемещение камеры — как раньше.
* Толщина контуров и линий оверлея масштабируется с расстоянием камеры
  (не тоньше ~2 px); подписи — фиксированного экранного размера.

## 20. Визуальный стиль и геометрия

* Стиль — минималистичный high-tech: технологическая площадка из
  объёмных гексагональных плит с фаской, тенями и различимыми
  материалами. Ориентир по читаемости — тактические игры вроде
  Arknights; модели, текстуры и интерфейс не копируются.
* Геометрия гексов вынесена в ядро (`Geometry/HexGeometry`, только
  числа): плита (верх, фаска, боковые грани до основания), углубление
  (кромка, внутренние стенки, дно на заданной глубине), поверхность
  жидкости (ниже кромки). Godot-слой лишь переводит её в меши — это
  позволяет тестировать «пол / возвышенность / яма» без движка.
* Внешний вид местности — блок «Вид» (`look`) в определении местности:
  материал (матовый, металл, глянец, стекло, жидкость, свечение,
  голограмма), основной и акцентный цвет, дополнительная высота плиты,
  фаска, прозрачность, свечение (цвет, сила), отбрасывание тени, контур
  (цвет, толщина), символ и узор (полосы, сетка, шевроны, точки, крест),
  глубина (для ям), анимация (поток, пульсация, блики).
* **Цвет не единственный признак**: опасные и специальные клетки
  дополнительно отмечаются узором и/или символом, ямы — светящейся
  кромкой и глубиной, барьеры — голограммой с шевронами.
* Встроенные типы: пол, возвышенность (платформа), яма, пропасть
  (провал без видимого дна), вода, лава, лёд, кислота, ядовитая
  поверхность, стена, разрушаемый контейнер, технобарьер, ловушка,
  подвижная/приподнятая платформа. Старые типы первой части сохранены
  (совместимость), их палитра приглушена под новый стиль.

## 21. Смертельные ямы

* Блок «Яма» в определении местности: проходимость (можно ли войти),
  смертельность, урон при падении (если не смертельна), последствие
  (`Death` — гибель, `Damage` — урон и возврат на последнюю безопасную
  клетку, `Stun` — урон и оглушение на дне, `Remove` — убрать из боя
  без гибели), слои, на которые действует (по умолчанию только
  наземный), теги и состояния спасения/иммунитета, анимация падения
  (провал, растворение, уменьшение) и её длительность.
* Падение происходит при входе в клетку-яму наземного юнита без
  иммунитета: толчок/притяжение, телепорт, смена местности под юнитом,
  ход по собственной воле (маршрутизатор не прокладывает путь через
  ямы для тех, на кого они действуют). Пересечь яму позволяют навыки
  перемещения (прыжок, рывок, телепорт — переносят исполнителя мгновенно)
  и спасающие состояния (например, «Левитация»: пока действует, яма не
  действует на юнита и по ней можно идти; закончилось над ямой — падение).
* Гибель от падения проходит через общую процедуру смерти: очередь
  очищается, подготовка прерывается, резервы клеток снимаются, связи
  блокирования разрываются, автоатаки прекращаются, юнит исключается из
  расчётов целей, видимости и сценария. Причина гибели — «падение».

## 22. Слои положения существ

* Новая категория **«Слой»**: `ground` (наземный), `air` (воздушный),
  `underground` (подземный) и пользовательские. Параметры слоя: высота
  отображения, игнорирование стоимости местности и правил высоты,
  преодолеваемая высота препятствий, иммунитет к ямам, скрытность
  (виден только наблюдателю с характеристикой обнаружения слоя или
  вплотную), блокируемость по умолчанию, с какими слоями сталкивается.
* Юнит находится в одном слое (`layer` в определении, меняется операцией
  «Сменить слой»: взлёт, приземление, зарывание). Пустое значение —
  `ground` (совместимость: старые «летающие» по категории движения
  `fly` остаются в наземном слое, пока им явно не задан `air`).
* Занятость клеток считается **внутри слоя**: летящий над клеткой не
  мешает стоящему на ней.
* У навыка — список допустимых слоёв целей и слоёв исполнителя; пустой
  список — значение по правилам: ближний бой → `ground`, дальний бой и
  заклинания → `ground, air`. Подземных поражают только навыки и
  эффекты, явно включающие `underground`.
* У эффекта клетки — список слоёв, на которые он действует (по умолчанию
  `ground`).

## 23. Направление взгляда врагов

* Блок «Восприятие» юнита: режим взгляда — `Single` (одно направление,
  как в первой части), `Multiple` (дополнительные направления, задаются
  смещением от основного), `Omni` (круговое), `None` (без направления).
  Дополнительно — зона обнаружения (конус, линия, сектор, радиус),
  ограничивающая видимость.
* Для `None` и `Omni` секторы атаки не применяются: используется правило
  «без секторов» (по умолчанию шанс заметить 100 %, неожиданность 0 %),
  которое можно переопределить у юнита. Для `Multiple` сектор
  определяется по ближайшему к фронту из направлений.
* Юниты без направления не тратят ОД и время на поворот; индикатор
  взгляда: стрелка (одно), несколько стрелок, кольцо (круговое), нет.

## 24. Информация о врагах и её раскрытие

* По клику на врага открывается информационная панель: имя и тип,
  здоровье, ресурсы, состояния и эффекты, известные сопротивления и
  уязвимости, известные навыки, направление взгляда, наблюдаемое
  намерение.
* Для каждой категории задаётся режим раскрытия: `Always` (всегда),
  `WhenVisible` (только пока виден), `AfterSeen` (после первого
  обнаружения; потом — последнее известное значение), `AfterObserved`
  (после наблюдения: навык — после того как игрок видел его применение,
  сопротивление — после попадания этим типом урона), `Never`. Глобальные
  значения — в правилах, переопределение — у типа юнита; панель можно
  отключить целиком.
* Знания хранит `KnowledgeSystem` симуляции (что сторона игрока видела и
  наблюдала). Туман войны ограничивает сведения: устаревшие значения
  помечаются временем. Административный режим видит всё.

## 25. Маркер предупреждения о появлении врагов

* Волна получает маршрут (`routes` карты — список точек; путь между ними
  строится по правилам движения врага без учёта юнитов) и интервал между
  появлениями. Для каждого запланированного появления создаётся маркер —
  данные симуляции, не боевой объект.
* Голова линии движется по будущему пути **с таймингом шагов этого
  врага** (стоимость клетки / скорость). Время пути `T`. Предупреждение
  начинается в `t_spawn − max(T, мин. предупреждение) − 1 с` и исчезает
  в `t_spawn − 1 с` (интервал исчезновения настраивается). Если путь
  длинный, маркер стартует раньше. Если голова дошла до конца раньше —
  линия остаётся полностью видимой до исчезновения.
* Вид: белая полоса толщиной ⅓ стороны гекса над поверхностью; режим
  «растущая линия» (по умолчанию) или «комета» (фиксированной длины).
* Время — симуляционное: пауза останавливает, ускорение ускоряет, тики
  не пропускаются. Смена маршрута/местности → путь пересчитывается.
  Отмена появления → маркер удаляется.
* Волны по событию (уничтожение группы, вход в область, устройство):
  появление откладывается на время предупреждения, чтобы маркер успел
  пройти путь.
* Отключение: глобально (правила), сценарий, волна, тип врага, точка
  появления — любое «выключено» скрывает маркер. Туман войны: `Show`
  (показывать), `Hide` (скрыть полностью), `AfterScouting` (только если
  точка появления была разведана), `Partial` (только участки по видимым
  клеткам). Скрытие маркера не влияет на появление врага.

## 26. Совместное нахождение на гексе

* Блок «Совместное размещение» типа юнита: разрешено ли, предел существ
  на гексе, категории существ, с которыми разрешено, влияние скопления
  (доп. стоимость движения и штраф точности за каждого соседа по
  клетке), раскладка группы (кучка, ряд, кольцо).
* Войти в клетку можно, если все живые существа этого слоя в ней не
  враждебны, взаимно разрешают совместное размещение и предел не
  превышен. Каждый остаётся отдельной сущностью.
* Флаг сценария первой части `allowStacking` заменён режимом
  `stacking`: `ByUnitType` (по умолчанию), `ForbidAll`, `AllowAll`
  (старое `true`, миграция v1 → v2).
* Интерфейс: на клетке с несколькими существами фигуры раскладываются
  (кучка/ряд/кольцо) и уменьшаются, у первой — значок «×N»; полоски
  здоровья — только у первой и у выбранной. Клик выбирает фигуру,
  ближайшую к курсору, и открывает полоску выбора над панелью юнита;
  повторный клик по выбранной или Tab (Shift+Tab — назад) листают
  существ гекса; Esc закрывает полоску, после чего Tab снова листает
  своих юнитов (поведение первой части).
* Стартовая расстановка сценария проверяется по тем же правилам
  (взаимное разрешение типов, предел, враждебность, слой), а не
  запретом «один юнит на клетку».

## 27. Блокирование

* Новая характеристика **«Лимит блокирования»** (`block_limit`, по
  умолчанию 0) — сколько слотов врагов юнит может держать; меняется
  модификаторами навыков, состояний и пассивок. Не путать с «шансом
  блока удара» (`block_chance`) первой части.
* Блокирующий: категории и слои блокируемых врагов, зона (все соседние
  клетки, только фронтальная дуга, только своя клетка), может ли
  блокировать в движении, под контролем.
* Блокируемый: можно ли блокировать, нужен ли блокирующему тег
  специальной способности, расход слотов (босс — 2–3), может ли обходить
  блок, поведение при блоке (атаковать блокирующего, ждать, искать
  обход).
* Связи пересчитываются **каждый тик** из текущего состояния, с
  сохранением существующих связей в приоритете, — поэтому исчезнувший,
  оттолкнутый, оглушённый блокирующий или потерявший лимит не оставляет
  «вечной» блокировки.
* Три ситуации различаются явно: 1) **заблокирован** — враг не может
  продолжить движение и атакует блокирующего; 2) **удерживается** —
  состояние с запретом движения или замедлением, наложенное навыком;
  3) **не блокируется** — продолжает движение (нет слота, обход,
  несовместимость).
* Связь возникает, когда враг с приказом движения находится в зоне
  блокирующего (в том числе посреди шага); заблокированный дошагивает
  текущий шаг и дальше не идёт — ОД и время ожидания не тратятся,
  команда в статусе «ждёт: заблокирован». «Искать обход» — путь в обход
  зоны блокирующего; найденный обход снимает связь и даёт 2 с без
  повторного блока. Летающие и подземные по умолчанию не блокируются
  (свойство слоя «блокируется»); блокирующему можно явно указать слои.
* Интерфейс: «Блок 2/3» у блокирующего (подпись и строка в панели со
  списком удерживаемых), оранжевая цепь между блокирующим и врагом,
  подписи «заблокирован» / «удерживается» у врага.

## 28. Автоатаки

* Список автоатак у типа юнита (союзники и враги одинаково): навык (по
  умолчанию — обычная атака), дальность (переопределение), допустимые
  цели и слои, требования обнаружения и линии видимости, стоимость ОД
  (по умолчанию из навыка), интервал, правила выбора цели, атака в
  движении, при блокировании/будучи заблокированным, условия
  прерывания, поведение при нехватке ресурсов (пропустить, ждать,
  тратить зарезервированные ОД).
* Выбор цели: последовательные правила (первое правило, давшее
  кандидатов; ничьи — следующим правилом) или взвешенная сумма.
  Правила: ближайший, наименьшее HP, наименьшая доля HP, самый опасный,
  ближайший к защищаемому объекту, босс, с тегом, блокируемый мной,
  блокирующий меня, текущая цель. Случайный выбор среди равных —
  только по флагу и только через генератор симуляции.
* Алгоритм (каждый тик): готовность → ОД/ресурсы → момент атаки →
  кандидаты (обнаруженные стороной) → дальность/видимость/слой (общая
  проверка навыка) → выбор → запуск навыка тем же путём, что и команда
  → общий расчёт урона и состояний → событие и следующий момент.
* Автоатака использует только **свободные** ОД (не трогает резерв
  очереди), не срабатывает во время выполнения команды-навыка игрока;
  ручные команды имеют приоритет. Возвышенность сама бонусов не даёт:
  дальность, обзор и точность от высоты — отдельные правила (§4 и §9
  части 1, их можно обнулить).

## 29. Единый расчёт урона

Все источники (навык, автоатака, эффект клетки, местность, состояние,
синергия, отражение, падение, сценарий, пассивка) проходят один
конвейер `DamagePipeline`:

1. Источник, тип урона, исходное значение.
2. Допустимость цели (слой, жизнь) и иммунитет.
3. Бонусы атакующего и навыка (характеристики урона по типу/категории,
   неожиданность).
4. Попадание и уклонение (бросок — только для источников с флагом).
5. Критический удар.
6. Преобразование части урона в другой тип, затем сопротивления и
   уязвимости: `D = D₀ × max(0, 1 + ΣV/100)`, `V ∈ [−500; +500] %`,
   положительное — уязвимость, отрицательное — сопротивление; суммируются
   все подходящие модификаторы (по типу, его предкам, элементу и его
   предкам, категории, `*`). Ниже −100 % урон равен 0, но **не лечит**.
7. Броня (для типов с флагом) и фиксированное снижение; блок удара.
8. Щиты (по приоритету, только защищаемые типы, кроме пробивающих).
9. Поглощение (процент, предел за удар/тик, в здоровье или ресурс).
10. Фактическая потеря здоровья.
11. Отражение (процент от фактического урона, тип исходный или
    заданный; отражённый урон по умолчанию не отражается — глубина 1).
12. Состояния, взаимодействия элементов и реакции.
13. Запись в журнал (в админ-режиме — подробный разбор шагов).

Исключения по источникам — таблица в правилах (бросок попадания, крит,
броня, щиты, поглощение, отражение, бонусы атакующего) — **все видны
в редакторе правил**. По умолчанию: только навыки и автоатаки бросают
попадание и критуют; периодический урон не критует; падение и «чистый»
урон игнорируют броню.

* Сопротивления первой части (доля `0.5`) мигрируют в модификатор `−50 %`;
  `1` → иммунитет. Характеристики `resist_<тип>` продолжают работать
  (значение × −100 %).
* Элементы — новая категория с родителем и наследованием (незаданное
  поле берётся у родителя; редактор показывает «унаследовано от …»).
  Базовые: огонь, вода, ветер, земля; продвинутые/редкие — потомки
  (молния, лёд, магма, яд, свет, пустота). Типы урона получили
  категорию (физический, магический, элементальный, окружение,
  пользовательский), родителя (режущий/дробящий/колющий — потомки
  физического) и элемент. Источник урона хранится отдельно от типа.
* Криты: шанс, множитель, фиксированный бонус, бонусы по виду атаки и
  сектору, защита от критов, иммунитет, крит-эффекты без доп. урона,
  флаг «может критовать» у навыка.
* Лечение: фиксированное, % от максимума, % от недостающего; усиление/
  ослабление (`heal_received`), запрет лечения (флаг контроля);
  избыточное лечение → щит (настройка).
* Щит — отдельный запас: объём, длительность, защищаемые типы, приоритет
  расхода, восстановление, правила пробития.
* DoT/HoT: интервал, длительность или число тиков, правила стакания,
  источник, условия снятия, сила — по моменту наложения или текущая.

**Реализация (этап 4).**

* Совпадение модификатора записывается строкой: `*` — любой урон, `id`
  типа урона (действует и на потомков), `el:id` — элемент (и потомки),
  `cat:Physical` / `cat:<своя категория>` — категория, `tag:x` — тег типа.
  В редакторе — один выпадающий список со всеми вариантами.
* Модификаторы берутся из типа юнита, его пассивок и уровней состояний
  (блоки «Защита от урона» и «Атака» одинаковы везде) и складываются;
  итог ограничен правилами (−500…+500 % по умолчанию). Старые
  характеристики `resist_<тип>` по-прежнему работают (доля × −100 %), их
  диапазон расширен до ±5 (±500 %).
* Взаимодействия элементов влияют на урон как модификатор на шаге 6
  («проводимость +50 %»), а их последствия (состояние, эффект клетки,
  снятие партнёра) — на шаге 12. Партнёр — состояние цели или эффект
  клетки под ней с элементом (или его потомком); так лава, лужа, пар
  участвуют во взаимодействиях наравне с навыками.
* Поглощение «в здоровье» возвращает поглощённую часть как лечение после
  удара (без силы лечения и щита от излишка); порядок относительно щитов
  задаётся у каждой записи.
* Формула урона правил (часть 1), если задана, заменяет шаги 5–7;
  переменная `resist` — доля (−ΣV/100).
* Миграция v3 → v4: `resistances` юнитов `{тип: доля}` → `defense.modifiers`
  (`0.5 → −50 %`, `−0.5 → +50 %`), `1` → `defense.immune`.

## 30. Опасная местность и эффекты окружения

* Моменты срабатывания эффекта клетки: вход, нахождение (тик), соседство
  (радиус), выход. Слои, тип урона, накопление (накопительное состояние:
  рост — очки за срабатывание, спад — у состояния), пороги и последствия
  (уровни состояния), защита (сопротивления, иммунитеты).
* Происхождение экземпляра: карта (свойство местности), карта
  (стартовый), навык, синергия, сценарий, распространение. Каждый
  экземпляр имеет уникальный ID.
* **Без двойного срабатывания**: за тик один юнит получает эффект одного
  определения из одной клетки один раз (самый сильный экземпляр), даже
  если эффект есть и от местности, и от навыка.
* Операции навыков: создать, удалить, усилить/ослабить (уровень),
  преобразовать (A → B), продлить.

## 31. Библиотека контента

* У каждого объекта: стабильный ID, **версия**, имя, категория
  (группа), теги. Имя меняется, **ID — нет** (противоречие с «переименованием»
  части 1 снято: «Переименовать» меняет имя; новый ID — только через
  «Дублировать»). ID нового, ещё не опубликованного объекта можно править.
* Версия увеличивается при публикации изменённого объекта; прежняя
  версия сохраняется в истории (`history/<категория>/<id>/v<N>.json`).
* Ссылка — `id` (следовать последней версии) или `id@N` (закреплённый
  экземпляр). Размещение юнита в сценарии и выбор карты закрепляют
  текущую версию — так шаблон в библиотеке, экземпляр в сценарии и
  состояние боя различаются. При публикации изменённого объекта, на
  который ссылаются, редактор показывает использования (включая
  косвенные) и предлагает: сохранить старые экземпляры (ссылки
  закрепляются на прежней версии), обновить выбранные, обновить все.
* Хранение — файловая структура JSON + манифест (SHA-256 файлов) +
  журнал транзакции. Публикация: резервная копия → журнал «запись» →
  атомарная запись файлов (временный файл + замена) → манифест → журнал
  снят. При запуске незавершённый журнал означает сбой — пакет
  откатывается к резервной копии с сообщением. Проверка целостности —
  по манифесту; повреждённые файлы отмечаются, их можно восстановить из
  копии. Несохранённые изменения — предупреждение при выходе.
* Поиск, фильтры (вид, группа, тег, ошибки, избранное, неполные),
  сортировка, избранное (личная настройка, не часть контента),
  зависимости («использует» / «используется в»), дублирование, массовые
  операции (удалить, экспорт, тег, группа, избранное).
* Пресеты правил — категория «Пресет правил»; сценарий может выбрать
  пресет вместо глобальных правил.

## 32. Пакеты импорта/экспорта

* Отдельный объект — `.json` (как в части 1). Пакет — `.hexpack` (ZIP):
  `manifest.json` (версия формата, ID и имя пакета, метаданные, список
  объектов с версиями, путями, SHA-256 и зависимостями, список ресурсов,
  отметка неполноты, общий хеш), `objects/<категория>/<id>.json`,
  `assets/...`. Только относительные пути; абсолютные пути и `..`
  отвергаются.
* Экспорт пакета собирает транзитивные зависимости и ресурсы.
* Импорт: проверка формата и целостности → совместимость версий
  (миграции) → зависимости (в пакете / в библиотеке / нет) →
  предпросмотр → конфликты ID → выбор разрешения (пропустить, копия с
  новым ID — ссылки внутри пакета переписываются, заменить — только с
  подтверждением, отменить весь импорт) → импорт в черновик → проверка
  → отчёт. Молчаливой перезаписи нет. Для обновления показывается
  разница полей. Без зависимостей импорт возможен только как
  **черновик** с отметкой «неполный» (такие объекты не используются в
  бою, пока ошибки не исправлены).

## 33. Редактор без программирования

* Единый каталог операций (эффектов) для навыков, пассивок, эффектов
  клеток, фаз боссов и триггеров: урон, лечение, ресурсы, ОД, состояния,
  накопление, эффекты клеток (создать/удалить/усилить/преобразовать),
  толчок/притяжение/поворот, изменение характеристик (временно,
  постоянно, до конца боя, пока выполняется условие, пока стоит на
  клетке, пока активен эффект), щит, временные модификаторы урона
  (сопротивление, поглощение, отражение, преобразование), призыв, смена
  маршрута и приоритетов ИИ, создание и разрушение препятствий, смена
  слоя, раскрытие информации, триггеры, визуальные и звуковые эффекты,
  фаза босса, сообщения, волны, цели, переменные сценария.
* Условия — дерево с `And/Or/Not`: здоровье ниже порога, цель в
  дальности, обнаружен противник, вход/выход из области, ресурс достиг
  значения, наложено состояние, таймер, объект уничтожен, цель выполнена/
  провалена, фаза босса, комбинация эффектов клетки, волны, утечки,
  удержание зоны, переменная.
* Формулы — только безопасный парсер (часть 1).
* Проверка перед публикацией: обязательные поля, диапазоны, ссылки,
  циклы триггеров, несовместимые эффекты, недостижимые цели,
  отсутствующие ресурсы, потенциально бесконечные реакции (циклы
  синергий, неоднократные триггеры с постоянно истинным условием).
  **Ошибки блокируют публикацию**, предупреждения принимаются
  подтверждением.

## 34. Модели, анимации, звуки, эффекты

* Новые категории: **«Ресурс»** (`assets.json`: модель glTF/GLB,
  текстура/спрайт PNG/JPEG/WebP, звук OGG/WAV, иконка; путь внутри
  `assets/`, SHA-256, настройки импорта, соответствие анимаций) и
  **«Визуальный эффект»** (пресет частиц + свет + звук).
* Базовая геометрия — заменяемое представление: если у типа юнита
  задана модель, она используется, иначе — фишка из примитивов.
  Анимации юнита: ожидание, движение, атака, навык, получение урона,
  блокирование, контроль, смерть, появление (для модели — клипы по
  таблице соответствия, для фишки — процедурные). Окружение: появление
  эффекта, срабатывание ловушки, разрушение, смена местности, падение.
* Безопасность: белый список расширений, проверка сигнатуры файла,
  предел размера, только относительные пути без `..`, glTF-буферы —
  только внутри пакета. Сцены Godot (`.tscn/.res`) и скрипты не
  импортируются — исполняемого кода в ресурсах нет.
* Отсутствующий или повреждённый ресурс → безопасная базовая
  геометрия/тишина + запись в диагностике ресурсов; приложение не
  падает.

## 35. Совместимость

* Версия формата контента — **2**. Миграция v1 → v2: сопротивления →
  модификаторы урона; условия победы/поражения → цели сценария; флаг
  совместного нахождения → режим; служебные поля (`any`) убраны.
  Карты, юниты и сценарии части 1 загружаются и играются.

## 36. Противоречия требований и принятые решения

| Противоречие | Решение |
|---|---|
| Часть 1: «переименование» объектов; часть 2: «ID изменить нельзя» | Переименование меняет имя; ID неизменен после публикации; новый ID — через дублирование. Ссылки остаются стабильными в пакетах и истории версий. |
| Часть 1: живые ссылки на шаблоны; часть 2: изменение шаблона не должно неожиданно менять сценарии | Ссылки с версией `id@N`; экземпляры в сценариях закрепляются; при публикации — диалог использований. |
| Часть 1: сопротивление — доля 0..1; часть 2: модификаторы −500…+500 % | Единый знаковый процент, миграция, характеристики `resist_*` пересчитываются. |
| Часть 1: «блок» — шанс отразить удар; часть 2: «блокирование» — удержание врагов | Разные характеристики: `block_chance` («шанс блока удара») и `block_limit` («лимит блокирования»). |
| Часть 1: флаг сценария «несколько юнитов на клетке»; часть 2: настройки по типам врагов | Режим сценария `ByUnitType/ForbidAll/AllowAll`. |
| Часть 1: юниты с движением `fly` — обычные цели; часть 2: ближняя атака не бьёт летящих | Слой задаётся явно; старые юниты остаются в наземном слое. |
| Часть 1: бонусы высоты к точности/дальности по умолчанию; часть 2: возвышенность не обязана давать бонусы | Бонусы остаются отдельными правилами (их можно обнулить); геометрия возвышенности на них не влияет. |
| Часть 2: «пользовательский шаблон» в списке встроенных | Генератор произвольного размера + шаблоны, сохранённые администратором. |
| Часть 2: волна «по событию» и маркер, который должен появиться заранее | Появление откладывается на время предупреждения после события. |
| Часть 2: маркер белый; «цвет не единственный признак» | Маркер — форма (полоса, движение), не только цвет. |
