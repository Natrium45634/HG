# Архитектурные решения — часть 4 (TD-редактор, базы, маршруты, волны, категории, автобой, оценка силы)

ТЗ четвёртой части — самостоятельный документ, дополняющий части 1–3.
Нумерация разделов продолжает [DECISIONS.md](DECISIONS.md) (§1–17),
[DECISIONS_2.md](DECISIONS_2.md) (§18–37) и [DECISIONS_3.md](DECISIONS_3.md)
(§38–54). Все числа — значения по умолчанию: правила и профиль проекта лежат
в `rules.json` (редактор «Правила боя»), сценарии — в `scenarios/*.json`.

Главные принципы не меняются: интерфейс не меняет бой напрямую, симуляция
детерминирована (seed), визуальное — только отображение. Новое для части 4:
**шаблон, категория, сценарий и оценка — четыре независимые сущности**
(ТЗ, «главный архитектурный вывод»):

* шаблон юнита (`UnitDef`) — что это за существо и как оно сражается;
* категории и теги (`OriginDef` + теги) — какие правила на него
  распространяются;
* сценарий (`ScenarioDef`: объекты, граф маршрутов, волны, события) — где,
  когда, сколько и куда появляются существа;
* оценка (`PowerModel`, `ThreatModel`) — только читает шаблон и контекст и
  никогда его не меняет; изменения (подгонка под уровень) — отдельная явная
  операция автора с отчётом и новой версией.

## 56. Объекты сценария и базы

* **Модель.** Новый список `ScenarioDef.Objects` (`ScenarioObjectDef`). У
  каждого — стабильный ID (префикс по типу: `base_<n>`, `spawn_<n>`,
  `checkpoint_<n>`, `tower_<n>`, `obj_<n>`; уникален в сценарии, не зависит от
  названия и положения), название, **тип** (база игрока, база спавна, точка
  маршрута, контрольная точка, сооружение, цель, точка взаимодействия, зона
  поведения, свой) и **компоненты**: занимаемые гексы (якорь + смещения,
  поворот по 6 направлениям), команда, здоровье и защита (макс. здоровье,
  броня, сопротивления по типам урона, восстановление, разрушимость),
  важность и приоритет защиты, спавн (§58), цель (роль в правиле
  поражения), взаимодействие (захват/ремонт/активация, время, кто может),
  триггер (события входа/выхода), зона (модификаторы ИИ и движения), вид
  (модель, эффекты), теги. Тип — только пресет: какие компоненты включены и
  с какими значениями; отдельный класс на каждый сюжетный объект не нужен.
* **В бою** объект со здоровьем — неподвижный юнит-сооружение: те же
  урон, состояния, щиты, журнал; занимаемые гексы непроходимы для
  наземных; **расстояние до сооружения считается до ближайшего его гекса**
  (одна функция дистанции для дальности атак, подхода и выбора целей).
  Объект без здоровья (точка, зона, контрольная точка) в бою юнитом не
  становится.
* **Несколько баз игрока**: у каждой — важность, здоровье, восстановление,
  разрушимость, приоритет защиты, допустимые маршруты. **Правило
  поражения** — поле сценария: любая база / все базы / главная база
  (указанная) / потеряно N баз / своё условие (дерево условий). Потеря
  вспомогательной базы может запускать события (§68), не завершая бой.
* **Враг достиг базы**: наносит базе урон «по базе» (характеристика
  `base_damage`, по умолчанию 25 при здоровье базы 500) и, если так задано (по умолчанию да), снимается
  с поля как «прорвавшийся». Старые цели «Защитить» с «допустимыми
  прорывами» работают как раньше (миграция — §73).
* **Проверка**: вся занимаемая область (не только якорь) — на карте,
  проходима для размещения, не пересекается с другими объектами.
* **Копирование** объекта даёт новый ID, ссылки на шаблоны, маршруты и
  ресурсы сохраняются; есть «дублировать только расписание».

## 57. Граф маршрутов

* **Модель** (`ScenarioDef.Routes` — список `RouteDef`, у каждого свой
  граф): узлы (`RouteNodeDef`: ID, гекс, тип — обычный, развилка, слияние,
  петля, контрольная точка, конец; правило выбора выхода; допустимые типы
  движения; ограничения; ссылка на событие) и рёбра (`RouteEdgeDef`:
  от/до, стоимость — длина пути по гексам × поправки опасности/замедления,
  ограничения по типу движения/тегам, направление, условие использования,
  приоритет, теги). Ребро — это путь по гексам между узлами (список гексов
  хранится, пересчитывается при изменении карты и проверяется).
* **Маршрут = граф с началом и целью**: начало — база спавна (или её
  точка появления), цель — объект (база игрока, цель, контрольная точка)
  или правило завершения («патруль», «стоять», «перейти к событию»).
  Обычный TD-маршрут обязан заканчиваться в назначенной цели; незавершённый
  маршрут сохраняется, но в сценарии не активируется без подтверждения.
* **Рисование**: в режиме «Маршруты» выбрать базу спавна → «Создать
  маршрут» → указать группы → протяжка ЛКМ по гексам. Линия идёт по центрам
  гексов; соседние гексы добавляются по одному (пропуск при быстром
  движении заполняется кратчайшим путём по проходимым гексам, так что
  «прыжков» через гексы нет). Во время рисования: текущий гекс подсвечен,
  пройденные — линией, недоступные — красным с причиной, пересечение с
  другим маршрутом — жёлтым, потенциальная развилка — ромбом, недопустимый
  конец — пояснением. Отпускание ЛКМ фиксирует маршрут и запускает проверку.
  Невалидный маршрут **не обрезается и не перенаправляется**: показывается
  причина и предложение («продлить до базы», «обойти по …», «отметить как
  патруль»).
* **Три операции различаются явно**: *пересечение* — два маршрута проходят
  через один гекс и остаются независимыми (по умолчанию, ничего не
  создаётся); *слияние* — конец ветки перетащен на узел другой ветки или
  команда «Соединить маршруты» (общий участок дальше); *развилка* — новая
  линия начата от существующего узла. Развилка требует правила выбора
  выхода: по весам (ГСЧ боя), по тегам/категориям группы, по условию, по
  загрузке (меньше врагов), первый доступный.
* **Петли**: ребро может вести в уже пройденный узел; у петли — число
  повторений, условие выхода, время пребывания, направление, поведение при
  обнаружении цели, разрешение атаковать и сменить маршрут. Петля с выходом
  к базе проверяется на достижимость выхода; петля без выхода допустима
  только с явной отметкой «бесконечный патруль».
* **Несколько маршрутов** используют общие гексы и рёбра свободно;
  ошибка — только логически неоднозначное или недостижимое продолжение.
  Приоритеты и разделение потока по тегам/условиям — правила развилок.
* **Проверка** (`RouteValidator`): начало связано с действующей базой
  спавна; конец — с допустимой целью; все обязательные узлы достижимы; нет
  шагов по непроходимым гексам для типов движения групп этого маршрута;
  ширина прохода подходит размеру юнитов (§60); у развилок есть правила;
  у петель — логика; условия не образуют тупиков; нет запрещённых
  повторяющихся рёбер; **после изменения карты** маршрут перепроверяется
  (сломанные рёбра — ошибка с местом). Серьёзность: критическая (сценарий
  не запускается), предупреждение, информация.
* **Совместимость**: старые маршруты карты (`MapRouteDef` — ломаная)
  читаются как граф из цепочки узлов; рисование кликами в редакторе карт
  остаётся, новое — в «TD-сцене».

## 58. Волны, группы, диспетчер, бюджет угрозы

* **Группа появления** (`SpawnGroupDef`, ID): шаблон юнита (ссылка; живая
  или закреплённая версия — §71), количество, начальная задержка,
  интервал, размер подгруппы и пауза между подгруппами, лимит живых
  экземпляров группы, маршрут (ID графа) и стартовый узел/цель,
  диапазон уровней экземпляров, локальные модификаторы характеристик,
  правило выбора маршрута, условия отмены и повторного запуска, база(ы)
  спавна. Группу можно сохранить как **пресет** (новая категория контента
  `GroupPreset`).
* **Волна** (`WaveDef`, расширенная): ID, название, номер, группы, задержка,
  условие запуска (таймер, после предыдущей, после уничтожения объекта,
  после контрольной точки, после появления врага, после смерти босса, по
  событию, вручную), условие завершения (все уничтожены, все дошли, убит
  конкретный враг, условие сценария, таймер, отменена событием), минимальный
  интервал до следующей, максимальная продолжительность, лимит живых,
  условие прерывания, награда/последствия (действия), модификаторы
  сложности. Условия — визуальный конструктор «Когда — если — тогда» (тот
  же редактор условий частей 2–3).
* **Диспетчер появления** — единая очередь заявок волн. Заявка создаёт
  юнита, только если: группа активна, её интервал/подгруппа наступили, не
  превышены лимиты живых (группы, волны, базы, сценария), не превышен лимит
  **созданных** (база, сценарий — отдельно от живых), сценарий не на паузе
  и выход не заблокирован. **Занятая область** — политика базы спавна:
  ждать освобождения / другой допустимый гекс области / ближайшая
  свободная позиция (ограниченный радиус) / отменить с записью ошибки.
  Телепортация в случайное место запрещена.
* **Бюджет угрозы**: волна в режиме «по бюджету» — автор задаёт бюджет и
  ограничения (мин./макс. число, разрешённые категории, обязательные и
  запрещённые теги, макс. доля элитных, обязательный лидер, предел
  стоимости одного шаблона, типы перемещения). Подбор — детерминированный
  (seed волны) жадно-случайный с проверкой ограничений; результат
  показывается списком групп и **закрепляется** кнопкой — закреплённый
  состав больше не меняется при перезапуске.
* **Совместимость**: старая волна (маркеры, один маршрут, список
  «юнит × количество») мигрирует в волну с одной группой на каждую строку
  состава, база спавна создаётся из маркера (§73).

## 59. Движение врагов, преследование, альтернативные цели

* Маршрут — основной план движения, но не запрет на бой. **Профиль
  поведения врага** — часть профиля ИИ (`AiProfileDef.Encounter`): режим
  (бегущий к базе, охотник, страж стаи, убийца, танк, поддержка), дистанция
  преследования, время отвлечения, допустимые цели (теги/категории/роль),
  условия возврата, приоритет базы, разрешение атаковать движущуюся цель и
  преследовать сквозь препятствия.
* **Возврат**: к ближайшему допустимому узлу своего маршрута (по
  стоимости пути, а не к последнему пройденному); недоступен — следующий;
  нет ни одного — сообщение о блокировке в диагностике.
* **Альтернативные цели** при уничтожении/недоступности основной базы — в
  профиле или сценарии: к другой базе (по важности), атаковать защитников,
  захватить объект, ломать препятствие, остановиться, отступить, событие.

## 60. Характеристики, вес, размер, перемещение

* Раздельно показываются: **база шаблона**, **итог после наследования**
  (категории, теги, пассивы — с источником каждого вклада), **временные**
  модификаторы, **динамика** в бою и **расчётная оценка** (§65). Пример ТЗ
  «волк 100 здоровья, категория +20 %» — база 100, вклад категории +20 %,
  итог 120; шаблон не меняется. Это уже обеспечивает разбор характеристик
  части 3 — добавляется явное разделение в редакторе юнита.
* **Новые характеристики**: `weight` (масса), `size` (размер), `base_damage`
  (урон по базе), `pursuit_range` (дальность преследования), `attack_speed`
  (скорость атаки, множитель частоты), `effect_duration` (продолжительность
  наложенных эффектов), `summon_power`; уже есть: здоровье, скорость, сила,
  магия, броня, сопротивления, точность, уклонение, дальность, обнаружение,
  подготовка, восстановление, контроль, лечение, щиты. Новые характеристики
  — данные (`StatDef`), формат шаблонов не меняется.
* **Размер** — юнит по-прежнему занимает один гекс (§73): размер влияет на
  проход через **узкие места** (гекс, у которого непроходимы два
  противоположных соседа, недоступен юнитам размера ≥ 2), на совместное
  размещение (занимает «мест» = размер) и на окружение. **Масса** —
  отбрасывание/притягивание (дистанция × эталонная масса / масса, не меньше
  0), разрушение препятствий таранящими, устойчивость. Вес не даёт здоровья
  и уровня, если так не задано формулой проекта.
* **Типы перемещения**: наземное, летающее, плавающее, подземное (слои
  части 2), **прыжковое** (может пересекать гексы с тегом `gap` — пропасть
  шириной 1, не останавливаясь на них), **телепортационное** (перемещение
  навыком; для маршрута — как наземное), свой. У юнита — список типов, у
  каждого необязательное условие (состояние, флаг, «навык активен»);
  проходимость — по любому действующему типу.

## 61. Дерево категорий и теги

* **Категории** — развитие «происхождений» части 3 (та же категория
  контента `Origin`, в редакторе — «Категории существ»): у категории
  появляется **родитель** (дерево любой глубины, циклы — ошибка), вид
  (раса, вид, класс, роль, своя) и **правила**. Существо имеет **основную**
  категорию (для отображения и библиотеки) и **дополнительные** (дают
  наследуемые эффекты), плюс теги.
* **Правило категории** (`CategoryRuleDef`, ID): что задаёт — пассивка
  (включая сопротивления, уязвимости, модификаторы характеристик,
  взаимодействия «против категории X»), тег по умолчанию, допустимый тип
  перемещения, запрет действия (стандартная атака / навыки с тегом / все
  навыки / движение), профиль ИИ по умолчанию, правило выбора цели, условие
  появления, ручной вклад в оценку силы; **режим наследования**:
  наследовать (как есть у родителя), дополнить (своё + родительское),
  переопределить (заменяет правило родителя с тем же ID), исключить
  (отключает правило родителя по ID), условно изменить (действует иначе при
  условии); приоритет; условие; область действия; порядок применения.
* **Разрешение**: правила собираются от корня к листу; одноимённые
  (по ID) — по режиму; правила разных дополнительных категорий —
  по приоритету, затем по глубине (ближе к существу — сильнее), затем по
  порядку категорий у существа. Противоречие при равном приоритете (запрет
  и разрешение одного действия) — **предупреждение** в редакторе с
  предложением выбрать режим; в бою действует детерминированный порядок.
* **Происхождение** каждого правила (шаблон, категория — какая, тег,
  состояние, сценарий) показывается в редакторе юнита и в разборе
  характеристик.
* **Теги** — метки без собственного эффекта: эффект появляется, когда на
  тег ссылается правило (условие, фильтр, модификатор). «Запрет стандартной
  атаки» запрещает только стандартную атаку, если автор не выбрал более
  широкий запрет.
* **Примеры** (контент этапа 4): дерево «Сущность → Живые → Звери → Волк →
  Волк-разведчик / Волк-вожак», «Слизи → Слизь-мимик / Кислотная слизь»,
  «Нежить», «Конструкты»; «Слизь-мимик» (наследует запрет стандартной
  атаки, маскировка, навык имитации объекта, атака из засады при появлении
  цели в радиусе); «Волк-вожак» (аура +15 % урона союзникам с тегом «Стая»,
  +5 % своей атаки за каждого учитываемого волка, не более +50 %, учёт
  мёртвых/призванных/вне ауры — настройки).

## 62. Пассивы, условия, стеки (дополнения к §46)

* Три типа уже есть: постоянные модификаторы, условные пассивы,
  срабатывающие реакции; активные навыки — отдельно.
* **Новые условия**: категория или тег (у владельца/цели/источника урона),
  слой, расстояние до цели, число стаков состояния, биом (тег местности),
  **время суток** и **погода** — переменные сценария (`Environment`),
  меняются событиями; экипировки в игре нет (§73).
* **Бонус «за каждого»**: модификатор с множителем «за каждого
  учитываемого юнита» (фильтр по тегам/категориям, сторона, радиус,
  учитывать ли призванных/мёртвых/вне ауры) и **пределом**.
* **Стеки**: к «один экземпляр / стаки» части 3 добавляются «обновлять
  длительность», «увеличивать стаки (до предела)», «запрещать
  дубликаты», «объединять по источнику»; самый сильный/слабый,
  сложение и перемножение — режимы суммирования части 3. Порядок обработки
  един для обычной игры и автобоя (это одна и та же симуляция).

## 63. Навыки (дополнения)

Типы эффектов ТЗ §9.1 уже есть (урон, DoT/HoT через состояния, лечение,
щит, изменение характеристик/сопротивлений/уязвимостей, замедление,
оглушение, обездвиживание, отбрасывание, притягивание, перемещение, призыв,
снятие состояний, смена ИИ и маршрута, метки, области). Добавляются:
воздействие на базу/объект (урон и ремонт сооружений через тот же конвейер),
смена маршрута **группы**. Запуск навыка и отдельные попадания уже
различаются (серии части 3) — отчёт автобоя считает и то и другое.

## 64. Автобой

* Одна и та же симуляция; режим «только логика» — без рендера и
  эффектов, результат совпадает с обычным боем тик в тик.
* **Режимы** (поле сценария): **TD с расстановкой** — фаза подготовки:
  длительность (или до подтверждения), доступные юниты и бюджет
  размещения (стоимость шаблона — по умолчанию его стоимость угрозы или
  ручная), лимиты по количеству, разрешённые зоны (гексы/объекты-зоны),
  перестановка между волнами, восстановление здоровья и ресурсов между
  волнами, условие начала первой волны; до подтверждения враги не
  появляются. **Свободный бой** — без маршрутов: юниты ищут противников по
  профилям ИИ. **Автотест** — без игрока: защитники по профилям ИИ и
  заданной расстановке.
* **Профили ИИ** (контент, 10 штук): страж, защитник базы, стрелок,
  убийца, поддержка, контролёр, охотник, вожак, прорыватель, патрульный —
  на параметрах профиля части 1 + визуальные правила «если — то — иначе» с
  приоритетом и действием (правила ИИ части 2 получают «иначе» и
  приоритет).
* **Отчёт прогона** (`BattleReport`): результат, завершённые волны, время,
  здоровье баз, погибшие защитники, убитые защитниками враги, достигшие цели
  враги, урон по сторонам, лечение, вклад щитов, применения навыков (запуски
  и попадания), срабатывания пассивок, урон по типам, время блокировки
  маршрутов, смены целей, ошибки ИИ (застрял, нет пути, цель недоступна),
  причины остановки/поражения. Собирается из событий симуляции наблюдателем
  (симуляция не меняется).
* **Пакетные прогоны**: N прогонов с seed = база + i (параллельно, каждый —
  своя симуляция; результат не зависит от числа потоков): процент побед,
  среднее волн, среднее/мин./макс. здоровье базы, частые причины поражения,
  разброс длительности. Результаты — в `user://reports/` (JSON + текст),
  отдельно от контента; прогон не меняет данные автора.
* **Скорости**: обычная, ускоренная (×2…×16), без визуальных эффектов,
  только логика, пошаговый режим, **остановка на событии** (смерть
  юнита с тегом, срабатывание пассивки, блокировка маршрута, враг у базы,
  начало/конец волны, своё условие).

## 65. Оценка силы и уровень

* `PowerModel` (ядро, без побочных эффектов) считает компоненты:
  **H** — эффективное здоровье (здоровье, щиты, броня, уклонение, блок,
  восстановление) **профилем по основным типам урона** (сопротивление
  −50 % → ×2, уязвимость +50 % → ×0,667); **D** — исходящий урон в
  секунду по каждому навыку: сила × множители ударов серии × число
  попаданий × вероятность попадания × охват области (ожидаемое число целей)
  ÷ (подготовка + восстановление + перезарядка), с учётом стоимости ресурса
  и вероятности прерывания; **R** — дальность (пороги зон поражения, атака
  через препятствия); **M** — мобильность (скорость, типы перемещения,
  рывки, отступление); **C** — контроль (длительность × шанс × охват);
  **S** — поддержка и синергии (лечение, щиты, ауры, бафы союзникам).
  Пассивы — с **ожидаемой долей действия** (условие «здоровье < 10 %» ≈
  10 % боя, аура — по контексту, срабатывание — по частоте события).
  Категории и теги дают вклад **только своими правилами**.
* **Профиль проекта** («Оценка силы» в правилах): эталонный юнит уровня
  1 (нормализация всех компонентов к нему), веса компонентов по ролям
  (танк, боец, стрелок, поддержка, контролёр, босс…), нелинейность
  (линейно, процент, пороги, убывающая отдача, пределы), шкала уровня
  (линейная, степенная, таблица порогов, своя по роли, отдельная для
  боссов). Изменение эталона пересчитывает все оценки — редактор
  предупреждает и показывает, у скольких шаблонов изменится уровень.
* **Отчёт** — таблица вкладов (здоровье и защита, урон, дальность и
  мобильность, пассивы, контроль, синергия, итог) с точным значением
  (10,37) и отображаемым уровнем (10); у каждого вклада — откуда он.
* **Контекст**: одиночная сила; в типичной группе (задаётся: N союзников с
  тегами); в группе сценария (из волн); против заданной категории. Рядом
  союзники не предполагаются, если контекст их не задаёт.
* **Ранг** (обычный, элитный, лидер, босс, свой) — отдельное поле шаблона;
  влияет на подбор волн, награды и вид, не на уровень.
* **Три уровня понятий**: оценочный уровень шаблона (расчёт), уровень
  экземпляра (группа задаёт диапазон; уровень экземпляра масштабирует
  характеристики экземпляра по профилю масштабирования, шаблон не
  меняется), масштабирование сложности (модификаторы волны/сценария).
* **Пересчёт** — при изменении шаблона, категории, навыка или пассивки
  (кеш по версии объектов, не при каждом изменении здоровья в бою);
  показывается, сколько волн/групп затронуто, и варианты (обновить ссылки,
  сохранить версию, оставить локальные переопределения, отменить).

## 66. Обратная сборка («Подогнать под уровень»)

* Профили масштабирования (данные): равномерный, танк, боец, дальний
  урон, убийца, поддержка, контролёр, босс, мобильный, свой — какие
  параметры можно менять и с какими весами.
* Ограничения каждого параметра: мин., макс., допустимый диапазон
  изменения, шаг, приоритет, запрет. По умолчанию меняются здоровье,
  атака, магия, защита, сопротивления, скорость, лечение, щиты,
  коэффициенты навыков; не меняются категория, обязательные теги, тип
  перемещения, ИИ, условия победы, критические механики.
* Алгоритм: исходная сборка сохраняется → исходная и целевая сила → поиск
  общего множителя профиля (бисекция) с соблюдением ограничений и шагов
  → перерасчёт → повтор до цели или пределов → отчёт. **Пропорции роли
  сохраняются** (масштабируются параметры профиля в одном отношении);
  недостижимо — «Максимальная оценка — 24,7: разрешите …».
* Варианты: безопасное увеличение базовых характеристик / усиление
  существующих навыков / комбинированное. Применение — только по
  подтверждению автора, результатом становится **новая версия или копия
  шаблона**, исходный не меняется.

## 67. Стоимость угрозы

* `ThreatModel`: скорость прохождения маршрута, вероятность дойти (эфф.
  здоровье против урона защитников), урон по базе, устойчивость к
  защитникам, обход (полёт, телепорт, прыжок), устойчивость к контролю,
  призыв, лечение и усиление группы, стоимость уничтожения, занимаемые
  гексы, атака защитников, взаимодействие с другими врагами.
* Показываются: базовая стоимость; в текущей карте (длина маршрутов,
  узкие места); против текущих защитников (их типы урона, наличие
  дальнобойных против летающих); на заданном маршруте. Подбор волн по
  бюджету берёт контекстную стоимость, если данных достаточно.

## 68. События сценария

* Правило = **событие → условия → действия** (триггер части 2 получает
  поле «событие»; без события — проверка условия каждый тик, как раньше).
* **События**: начало сценария, завершение подготовки, начало/завершение
  волны, появление юнита, смерть юнита, достижение цели, уничтожение базы,
  активация объекта, достижение контрольной точки, истечение таймера,
  превышение лимита живых врагов, выполнение условия, завершение боя; плюс
  события навыков и состояний. Фильтры события: объект, волна, группа,
  тег/категория юнита.
* **Действия** (к 26 существующим): активировать/отключить базу,
  запустить/остановить волну, изменить маршрут группы, создать юнита,
  изменить характеристики, установить цель, изменить состояние объекта,
  завершить сценарий, поставить симуляцию на паузу, записать
  диагностическое событие.
* **Защита от циклов**: статическая проверка графа «действие порождает
  событие, которое запускает правило» (появление → правило → создание юнита
  → появление); у правила — предел частоты (раз в N с) и максимум
  срабатываний; намеренный цикл (появление каждые 10 с) допускается только
  с явным пределом или условием завершения; в бою дополнительно —
  ограничение глубины цепочки (как раньше).

## 69. Интерфейс администратора

* **Рабочее место «TD-сцена»** (раздел редактора): карта в центре,
  слева библиотека объектов и шаблонов, справа свойства выбранного,
  снизу волны/расписание/тесты, сверху режимы и «Сохранить / Проверить /
  Запустить». Режимы: объекты, базы, маршруты, волны, зоны, категории,
  тестирование — каждый показывает только свои инструменты (в режиме
  маршрутов ЛКМ рисует, а не двигает объект); режим виден всегда.
* **Контекстное меню** (ПКМ по объекту): база спавна — настройки,
  добавить группу, добавить волну, создать маршрут, назначить цель,
  дублировать, проверить маршруты, тест с этой базы, удалить; маршрут —
  изменить, соединить, развилка, назначить группе, конечная цель,
  проверить достижимость, удалить; группа волны — шаблон, количество,
  интервалы, маршрут, модификаторы, дублировать, отключить.
* **Отмена/повтор** (Ctrl+Z / Ctrl+Y) в редакторе: снимок изменённых
  объектов до и после операции (`UndoStack`); составная операция
  (массовое изменение, подгонка уровня, рисование маршрута) — одна запись.
  Ctrl+Z в бою по-прежнему не используется (там Z — скорость).
* **Сохранность**: автосохранение черновика (есть), восстановление после
  сбоя (есть), **журнал последних изменений** (что, где, когда),
  подтверждение опасных операций, обнаружение несохранённого (есть),
  **точка восстановления** перед массовыми изменениями.

## 70. Диагностика и баланс

* **«Проверить сценарий»**: базы, маршруты, шаблоны групп, количества и
  интервалы, достижимость целей, конфликты категорий, ссылки навыков,
  циклы событий, допустимость характеристик — список с переходом к
  объекту (на карте выделяется).
* **Чрезмерно сильные юниты** — предупреждения с указанием правила:
  высокая устойчивость к нескольким типам урона, бесконечное лечение
  (восстановление ≥ входящего эталонного урона), неограниченный рост стаков,
  бесконечный призыв, чрезмерный множитель от союзников (без предела),
  дешёвый сильный навык, постоянное прерывание, недостижимая скорость,
  иммунитет к контролю + высокая мобильность. Ничего не запрещается.
* **Отчёт по волнам**: бюджет, фактическая стоимость, число врагов, средний
  и макс. уровень, ожидаемая длительность, достигнутые цели и средний урон
  по базе (из последних прогонов), сложность относительно предыдущей волны
  (скачок — выделен).
* **Сравнение версий шаблона**: характеристики, уровень, угроза, навыки,
  пассивы, сопротивления, роль, результаты тестов (если были прогоны обеих).

## 71. Шаблоны и экземпляры, версии

* Шаблон — `UnitDef` (+ новые поля: основная/доп. категории, ранг,
  профиль масштабирования, типы перемещения); экземпляр — группа волны или
  юнит сценария (ссылка на шаблон, уровень экземпляра, локальные
  модификаторы, параметры сценария) и юнит в бою.
* **Ссылка группы на шаблон**: живая (по умолчанию: изменения шаблона
  приходят в волны) или закреплённая на версии (`id@N`, снимок — механизм
  части 2). При публикации изменённого шаблона редактор показывает, сколько
  групп/волн затронуто, и предлагает: обновить все, закрепить старую
  версию, оставить локальные переопределения, отменить.
* **Локальные переопределения** группы (например, +10 % скорости) видны
  значком; «Превратить в шаблон» создаёт новый шаблон с этими изменениями
  и переключает группу на него.
* Изменение категории показывает затронутые дочерние категории и
  шаблоны; изменение маршрута — связанные группы.

## 72. Производительность

* Параметры проекта («Производительность» в правилах): макс. живых
  юнитов, макс. групп в волне, макс. узлов и рёбер маршрута, макс. правил
  пассивок, макс. одновременных эффектов, частота решений ИИ, число
  параллельных тестовых прогонов. Это не жёсткие пределы архитектуры, а
  пороги предупреждений.
* Пути рёбер маршрутов кешируются и пересчитываются только при изменении
  карты; оценки силы кешируются по версиям; решения ИИ — с частотой
  профиля; пассивы — по событиям и интервалу (часть 3).
* Превышение бюджета сценария — отчёт: какие подсистемы нагружены (по
  профилю пробного прогона), дорогие объекты, сколько юнитов будет создано,
  сколько эффектов одновременно, какие маршруты часто пересчитываются.
  Запуск теста при этом разрешён.

## 76. Ход реализации

### Этап 1. Базы и простые маршруты

* **Сооружение = неподвижный юнит.** Объект с компонентом «Здоровье и
  защита» в начале боя превращается в юнит (`StructureSystem`): шаблон
  строится из объекта (здоровье, броня, защита по типам урона, команда,
  теги `structure` и тип), юнит стоит на якоре и записан в обитателях
  всех своих гексов, поэтому гексы заняты для всех, а урон, щиты,
  состояния и журнал — общие с юнитами. Сооружение не толкают, ему нельзя
  отдать приказ (`CanPlayerCommand`), у него нет ОД; разрушенное остаётся
  руинами, гексы освобождаются.
* **Ближайший гекс.** `StructureSystem.AimCell` — единственная точка
  прицеливания по сооружению: дальность и линия видимости навыков,
  якорь области, повторное наведение серии, подход ближнего боя и выбор
  позиции стрелка ИИ считают до ближайшего гекса цели.
* **Прорыв.** Враг с целью-объектом, оказавшийся рядом с её гексами,
  записывается как «достиг» (событие в журнале), наносит враждебной цели
  урон `base_damage` и, если у объекта «прорвавшийся снимается с поля»,
  исчезает (причина «снят», без награды за убийство). Неразрушимый
  объект урон показывает, но здоровье не опускается ниже 1.
* **Правило поражения по базам** проверяется после обычных условий
  поражения; база из нескольких гексов разрушается как одно целое.
* **Маршрут этапа 1** — граф из двух узлов (начало, конец) и одного
  ребра; основной путь `RouteDef.MainPath()` — то же, что прежняя
  ломаная, поэтому движение по маршруту, предупреждение о появлении и
  действие «сменить маршрут» берут путь из одного места
  (`ScenarioSystem.RoutePoints`: маршрут сценария, иначе маршрут карты).
* **Группа волны** (`SpawnGroupDef`) появляется у своей базы спавна,
  идёт по своему маршруту к его цели (или своей); старые волны
  (состав + маркер карты) работают как раньше, включая время
  предупреждения. Занятый выход: «ждать», «другой гекс области»,
  «ближайший свободный» (по умолчанию) или «отменить с записью в журнал».
* **Рисование протяжкой** (`RouteDrawing`): гексы добавляются по одному;
  пропуск при быстром движении мыши заполняется кратчайшим проходимым
  путём для типов перемещения групп этого маршрута (сооружения, кроме
  цели, непроходимы), без «прыжков»; возврат на предыдущий гекс снимает
  последний; если прохода нет — рисуется прямая линия, а проверка
  называет непроходимый гекс. Гекс, на котором отпущена кнопка, — конец
  линии. Начало у конца существующей линии продолжает её. Линия **не
  обрезается и не перенаправляется**: короткий маршрут сохраняется с
  ошибкой «не доходит до цели» и предложением «Продлить до цели»
  (кратчайший проходимый путь от конца до соседнего с целью гекса).
* **Проверка сцены** (`ScenarioObjectsCheck`): ID, область объекта на
  карте и без пересечений, юниты не на сооружениях, база спавна с
  компонентом, правило поражения; маршрут — пуст, начало далеко от базы
  спавна, разрывы, вне карты, непроходимость для типа перемещения (с
  названием местности) или перепад высоты, проход через чужое
  сооружение, повтор гекса (предупреждение), цель не назначена/не
  найдена/не достигнута (ошибка; с «разрешить незавершённый» —
  предупреждение), патруль/стоять — сведения; группы — шаблон, база,
  маршрут, начало маршрута у другой базы, неизвестная цель, повтор ID.
  Ошибки проверки — ошибки публикации сценария; «▶ Запустить бой» в
  TD-сцене не запускает сцену с критическими ошибками.
* **Рабочее место «TD-сцена»** — новый раздел редактора над теми же
  сценариями: режимы «Объекты и базы», «Маршруты», «Волны»; библиотека
  режима слева, свойства выбранного справа (ID баз и маршрутов выбираются
  из списка сцены), проблемы снизу (клик — к объекту и гексу). Боковые
  панели держат ширину, чтобы окно карты не менялось посреди жеста
  (иначе камера перевписывается и протяжка «съезжает»).
* **Отложено**: в меню ПКМ базы спавна — «добавить волну», «назначить
  цель», «тест с этой базы» (этапы 2 и 5); меню маршрута и группы,
  развилки и слияния (этап 3); отмена/повтор (этап 7) — пока изменения
  отменяются кнопкой «Отменить» черновика.

### Этап 2. Волны и очереди

* **Группа** получила подгруппы (размер и пауза: внутри подгруппы — интервал,
  между подгруппами — пауза вместо интервала), лимит живых группы,
  дополнительные базы спавна (враги распределяются по базам по очереди,
  основная — первая), повторы (число и период от начала предыдущего
  выхода; число ограничено 100 — бесконечного цикла нет), модификаторы
  экземпляров (`StatModDef`, только у врагов группы), условие отмены,
  ссылку на пресет и отметку «подобрана по бюджету».
* **Волна** — ID, максимальная продолжительность (по истечении оставшиеся
  появления отменяются, живые остаются), минимальный интервал до
  следующей (сдерживает следующую волну, кроме волн по времени, — от
  начала этой), условие прерывания (волна отменяется в любом состоянии до
  зачистки), сложность (множители здоровья, силы и магии, скорости и
  количества — модификаторами экземпляра с подписью источника; количество
  округляется вверх), бюджет угрозы. Условия запуска из ТЗ выражаются
  существующими: «после уничтожения объекта» — «юнит с меткой погиб»
  (метка сооружения — ID объекта), «после контрольной точки» — «юнит
  стороны в области», «после появления врага» — «волна началась», «после
  смерти босса» — «юнит с меткой погиб», «по событию» — «флаг события»,
  «вручную» — «только действием триггера».
* **Диспетчер.** Появление проверяет лимиты по порядку: созданных (база,
  сценарий — исчерпан → появление **отменяется** с записью, это не «ждать»),
  затем живых (волна, группа, база, сценарий — нет места → появление
  **ждёт**, его линия предупреждения снимается, причина пишется в журнал
  и показывается в панели волн боя). Освободилось место — ждущее
  планируется заново (с новой линией); уже перепланированные держат своё
  место, чтобы одно освобождение не перепланировало сразу несколько.
  Лимиты считаются по врагам волн (сооружения и юниты сцены не входят).
* **Модификаторы экземпляра** (`Unit.InstanceMods`) — отдельный источник,
  переживает каждый пересчёт характеристик (состояния, пассивы), виден в
  разборе характеристики; шаблон не меняется; здоровье при появлении —
  полное с учётом множителя.
* **Стоимость угрозы** (`ThreatCost`): значение автора в шаблоне или
  оценка — прочность (здоровье × броня × уклонение) / 25 × атака (сила и
  магия, дальность обычной атаки), босс ×1.5, шаг 0.5. Этап 6 заменит
  оценку моделью силы; значение автора остаётся главнее.
* **Бюджет угрозы** (`WaveBudget`): кандидаты — шаблоны фракции волны с
  ненулевой скоростью, по категориям существ, обязательным и запрещённым
  тегам, типам перемещения и пределу стоимости; лидер — первым (дороже
  бюджета — проблема, но в составе); затем случайный выбор среди
  доступных по оставшемуся бюджету (ГСЧ симуляции с seed волны — свой
  или от seed сцены и номера волны), элитные (тег `elite` или босс) — не
  больше доли от состава; меньше минимума — проблема. Незакреплённый
  бюджет подбирается при каждом запуске (seed сцены одинаков — состав
  одинаков); «Закрепить» записывает состав группами волны (отметка
  «подобрана по бюджету»), дальше он не меняется; «Снять» удаляет эти
  группы. Проблемы подбора — предупреждения проверки сцены.
* **Пресет группы** — новая категория контента `GroupPreset`
  (`group_presets.json`, раздел редактора «Пресеты групп»): группа без
  базы, маршрута и цели; применение копирует её в волну с новым ID и
  привязкой к выбранной базе и её маршруту.
* **Формат 5** (миграция 4→5 в `ContentMigrator`): строки состава старой
  волны → группы (`w<N>_g<M>`), маркеры появления → базы спавна
  `spawn_<маркер>`, привязанные к маркеру карты (якорь берётся с карты при
  загрузке боя и проверке — `ScenarioObjects.ResolveMarkers`), с политикой
  «ближайший свободный» в радиусе 4 (как прежний поиск клетки); задержка
  группы = интервал × номер первого её врага, доп. базы — в порядке
  очереди маркеров, так что i-й враг волны выходит в то же время и из той
  же точки. Маршрут карты остаётся маршрутом группы (ID маршрута карты
  допустим). Проверено: встроенные сценарии до и после миграции дают
  одинаковые планы, юниты, позиции и исход за 120 с; тест ядра сравнивает
  то же на сцене с двумя маркерами, лимитом и волной «после
  предыдущей». Группа без маршрута — сведение, а не предупреждение
  (обычный не-TD сценарий).
* **Редактор «Волны»**: библиотека шаблонов карточками (название, угроза,
  здоровье, категория, перемещение; поиск по названию/ID/тегу, фильтры
  команды, категории, перемещения; сортировка по угрозе; клик — группа в
  выбранной волне у выбранной базы с её маршрутом), пресеты групп
  («Сохранить как пресет» у группы, клик по пресету — группа), бюджет
  волны («Подобрать» — состав и затраты, «Закрепить», «Снять»),
  расписание (время от начала боя для волн по времени, от начала волны
  для остальных). В бою — панель волн: прогресс и причина ожидания.

### Этап 3. Граф маршрутов

* **Движение по графу** (`RouteNavigator`): враг идёт по рёбрам; дойдя до
  конца ребра, проходит узел (флаг узла — для триггеров и условий;
  ожидание в узле), затем правило узла выбирает следующий выход среди
  доступных: условие ребра выполнено, все его гексы проходимы для типа
  перемещения врага (проверяется в бою — карта могла измениться),
  петля не исчерпана. Правила: «первый доступный» (по приоритету),
  «по весам» (ГСЧ боя — воспроизводимо по seed), «по тегам и категориям»
  (теги шаблона, категория существа, метка, группа, ID шаблона; иначе —
  выход без тегов), «по условию», «по загрузке» (где сейчас меньше врагов),
  «по очереди». Нет доступного выхода — запасной маршрут маршрута (с
  ближайшего узла), иначе враг ждёт в узле и объясняет почему. Выходов нет
  совсем — конец (патруль начинается заново).
* **Петли**: ребро, ведущее в уже пройденный узел, получает настройки
  петли (повторений, условие выхода, «атаковать по пути»). Лимит
  считается по ребру с настройками и запрещает **вход** в цикл из узла,
  где есть другой путь; внутри цикла враг всегда может вернуться к этому
  узлу (не запирается). Цикл без лимита и условия — ошибка проверки, если
  маршрут не «бесконечный патруль»; в бою неуправляемый цикл
  останавливается после 10 000 рёбер с записью (только черновик).
  Обратное направление прохода петли не вводилось.
* **Пересечение ≠ слияние ≠ развилка**: маршруты, проходящие через общий
  гекс, независимы (ничего не создаётся); ветка, начатая от узла или линии
  маршрута, — развилка (линия разбивается узлом); ветка, законченная на
  узле или линии своего маршрута, — слияние (или петля, если узел
  позади); «Соединить маршруты» копирует часть другого маршрута от его
  ближайшего узла (общий участок дальше), другой маршрут не меняется.
* **Основная линия** (`MainPath`) — первый выход каждого узла, причём
  выходы вне петель первыми: её используют предупреждение о появлении,
  проверка «доходит до цели» и подписи.
* **Несколько маршрутов у группы**: основной и «другие маршруты», выбор —
  по очереди или случайно (ГСЧ боя), цель — у каждого маршрута своя.
* **Смена маршрута в бою** (действие триггера, эффект навыка) ставит на
  граф с ближайшего узла нового маршрута; маршрут карты (точки) — как
  раньше.
* **Проверка графа**: ребро ссылается на существующие узлы и доходит до
  своего узла, все гексы каждого ребра соседние, на карте и проходимы
  (для всех типов перемещения групп маршрута), узлы достижимы от начала
  (иначе предупреждение), ветка, обрывающаяся не у цели, — ошибка (с
  «разрешить незавершённый» — предупреждение), развилка «по весам» с
  нулевыми весами — ошибка, «по условию» без условий и «все выходы с
  условиями» — предупреждения, петли без выхода — ошибка, нет выхода к
  концу маршрута — ошибка, запасной маршрут не найден — ошибка. Проверка
  идёт по текущей карте, поэтому после изменения карты сломанное ребро
  сразу видно — с гексом — и в TD-сцене, и в проверке публикации.
* **Редактор «Маршруты»**: протяжка от узла или линии выбранного маршрута —
  ветка (начатая в стороне от маршрута — подсказка «начните у узла или
  Перерисовать»), конец на маршруте — слияние/петля, от конца — продление;
  во время протяжки — ромбы возможной развилки и слияния; клик по узлу —
  его свойства (тип, правило, ожидание, флаг) и свойства каждого выхода
  (приоритет, вес, теги, условие, петля) с удалением выхода (и всего, что
  стало недостижимым); «Продлить до цели» достраивает ветку от конца
  основной линии; «Соединить с выбранным»; запасной маршрут — из списка
  маршрутов сцены. На поле узлы различаются формой: начало — кольцо,
  развилка — ромб, слияние — малое кольцо, контрольная точка — пунктир,
  конец — точка; петли — тоньше.

### Этап 4. Категории, теги, пассивы

* **Категории = происхождения части 3** с родителем и правилами
  (`OriginDef.Parent`, `OriginDef.Rules`); раздел редактора называется
  «Категории существ». У шаблона — основная категория (`MainCategory`) и
  дополнительные (прежний список «Происхождения»), плюс категории по
  тегам автоназначения. Пассивы происхождения части 3 читаются как правила
  «Дополнить» (каждый со своим ключом).
* **Правило** (`CategoryRuleDef`): пассив, тег, допустимый тип
  перемещения, запрет действия, разрешение действия, профиль ИИ по
  умолчанию, ручной вклад в оценку силы (используется этапом 6); ID,
  приоритет, режим, условие.
* **Режимы** по цепочке от корня к листу: «наследовать» — передаётся
  потомкам как есть (совпадение ID с правилом родителя — предупреждение,
  действует родительское); «дополнить» — оба правила действуют;
  «переопределить» — заменяет правило родителя с тем же ID;
  «исключить» — отключает правило родителя (исключать нечего —
  предупреждение); «условно изменить» — пока условие выполнено, действует
  это правило, иначе — родительское. Для пассивов условие проверяется в
  бою на каждой проверке пассивов; для тегов, типов перемещения и запретов
  — при появлении юнита.
* **Несколько категорий**: правила с одним ключом из разных цепочек —
  по приоритету, затем по глубине (ближе к существу сильнее), затем по
  порядку категорий у шаблона (основная первой); общий предок учитывается
  один раз. Запрет и разрешение одного действия: сильнее по тем же
  признакам; при равном приоритете — предупреждение проверки (с указанием,
  что действует) и детерминированный порядок. Цикл в дереве и родитель,
  которого нет, — ошибки категории.
* **Запрет действия** снимает возможность при появлении: стандартная атака
  (у юнита нет обычной атаки), навыки с тегом, все навыки, движение
  (скорость ×0 модификатором экземпляра). Поэтому запрет одинаково
  соблюдают приказы игрока, ИИ и автоатаки; приказ на запрещённое
  действие отклоняется с причиной («запрещено: стандартная атака
  (категория «Слизи»)»). «Запрет стандартной атаки» не трогает навыки.
* **Теги**: у юнита — теги шаблона, теги его категорий и метка сценария
  (`Unit.HasTag`); принадлежность к категории — вместе с предками
  (`Unit.InCategory`). Все проверки «tag:», «тип существа», фильтры
  блокирования, групповых приказов, правила выбора цели, развилок «по
  тегам», бюджета волн и «за каждого» используют их. В условиях тип можно
  указать ID категории дерева (или «cat:ID»).
* **Профиль ИИ категории** действует, если у шаблона профиль пуст
  (сценарий и группа волны по-прежнему главнее).
* **Новые условия юнита**: категория или тег, слой, расстояние до цели,
  переменная сценария; число стаков состояния и биом (тег местности) уже
  были («есть состояние» со значением, «стоит на поверхности» с «tag:»).
* **Переменные сценария** (`ScenarioDef.Environment`): время суток, погода
  — начальное значение, подпись; меняются действием триггера «изменить
  переменную сценария», проверяются условием сценария и условием юнита. В
  бою — строка в панели целей («Время суток: ночь»); при `time_of_day =
  night` поле затемняется (только вид, правила видимости не меняются).
* **«За каждого»** (`ModifierDef.PerEach`): величина модификатора ×
  число учитываемых юнитов (типы, сторона, радиус, себя, призванных,
  погибших, вне радиуса), с пределами величины и количества; считается
  для владельца (у копии ауры — для владельца ауры) на каждой проверке
  пассивов; изменение числа пересчитывает характеристики. Стеки
  умножаются после.
* **Аура только для**: фильтр получателей ауры по тегам и категориям.
* **Стеки**: к «один экземпляр» и «стаки» добавлены «по экземпляру от
  каждого источника» (две ауры разных владельцев действуют обе — различие
  по владельцу, даже при одинаковых именах) и «запрещать дубликаты»
  (действует первый источник, остальные перечислены как
  проигнорированные). «Обновлять длительность» — уже поведение
  срабатывающих пассивов (новое срабатывание продлевает действие).
* **Характеристики тела**: «Масса» (по умолчанию 100) — дистанция
  отбрасывания/притягивания × эталон (правило, 100) / масса, вниз;
  «Размер» (1) — от «размера для узких мест» (правило, 2) существо не
  входит в гекс, у которого два противоположных соседа непроходимы для него
  (или вне карты); «Дальность преследования» — для ИИ этапа 5.
  «Скорость атаки», «продолжительность эффектов», «сила призыва» как
  отдельные характеристики не вводились: скорость каста уже есть
  (`cast_speed`), остальное задаётся модификаторами навыков.
* **Типы перемещения**: дополнительные типы шаблона с условием
  (`MoveTypes`) и типы от категорий; проходимость — по любому
  действующему типу (основному или дополнительному) везде, где она
  проверяется (движение, отбрасывание, смена местности, развилки).
  Прыжковое перемещение через пропасть «не останавливаясь» и
  телепортационное (как отдельный тип пути) не вводились — см.
  ограничения этапа.
* **Контент**: дерево «Сущность → Живые → Звери → Волк → Волк-разведчик /
  Волк-вожак», «Сущность → Слизи → Слизь-мимик / Кислотная слизь» (бывшая
  «Слизь»), «Нежить», «Конструкты»; шаблоны «Волк-разведчик», «Волк-вожак»
  («Вой вожака» — аура +15 % урона союзникам с тегом «pack»; «Сила стаи» —
  +5 % урона за каждого волка стаи в радиусе 3, не более +50 %, погибшие
  не учитываются, призванные — учитываются), «Слизь-мимик» (наследует
  запрет стандартной атаки; «Имитация предмета» — скрытность, раскрытие
  имени и навыков после наблюдения; «Засада» — «Удар из засады», когда
  противник подходит на 2 гекса); у волков категории — «Ночной охотник»
  (+20 % скорости, пока ночь). Сцена «Ночная охота стаи».


### Этап 5. Автобой и ИИ

* **Режим боя** (`ScenarioDef.Mode`): «обычный бой» (как раньше), «TD с
  расстановкой», «свободный бой», «автотест». Режим выбирается в
  свойствах сцены (группа «Автобой») или в TD-сцене, режим «Расстановка и
  зоны».
* **Подготовка** (`PlacementDef`, `Sim/PlacementSystem`): конец подготовки
  — подтверждение, время, подтверждение или время, условие; бюджет (0 —
  без ограничения), «не более юнитов», доступные шаблоны (стоимость — своя
  или стоимость угрозы, «не более», профиль ИИ, улучшение и его цена),
  зоны — гексы, отмеченные на карте, и объекты-зоны с радиусом (зон нет —
  радиус вокруг баз игрока), «враги до подтверждения» (по умолчанию нет),
  перестановка между волнами, доля восстановления здоровья и ресурсы между
  волнами, расстановка по умолчанию и профиль защитников для автотеста.
  Пока идёт подготовка, волны, цели, боссы и проверка исхода стоят;
  «прошло N с», лимит времени и волны по времени считаются **от конца
  подготовки** (`ScenarioSystem.BattleTime`), без подготовки — от начала,
  как раньше. Снять защитника (бюджет возвращается) можно только в
  подготовке; переставить — в подготовке и между волнами (ни одна волна
  не идёт); улучшить — заменить шаблоном улучшения на том же гексе.
  «Строительство сооружений» — это размещение шаблонов-сооружений тем же
  способом (неподвижные шаблоны), отдельной экономики строительства нет.
* **Свободный бой**: волны появляются без маршрутов (маршрут группы
  игнорируется), враги без видимого противника идут к ближайшему юниту
  другой стороны («ищет противника»), дальше — по профилю. Удерживающие
  позицию профили не уходят.
* **Автотест**: стороны игрока управляются ИИ (`SimOptions.AutoPlayer`);
  профиль защитника — из расстановки, иначе «профиль защитников» сцены,
  иначе «Страж» (`ai_guard`), если он есть; расстановка по умолчанию
  ставится при загрузке (без бюджета и зон — это авторская расстановка).
  Сцену «TD с расстановкой» автобой играет так же: ставит расстановку по
  умолчанию и подтверждает подготовку.
* **Правила ИИ «если — то — иначе»** (`AiRuleDef`): приоритет, условие,
  «то: поведение» и «то: действия», «иначе: поведение» и «иначе:
  действия», однократно/перезарядка (для каждой ветви отдельно). Правила
  проверяются каждый тик от большего приоритета; **поведение** на этот тик
  задаёт первое правило, у сработавшей ветви которого оно есть; действия
  выполняются у всех. Поведения (`AiDirective`): атаковать по приоритету
  профиля, слабейшего, опаснейшего, угрожающих базе; отступить; удерживать
  позицию; идти к цели, не отвлекаясь; лечить и усиливать; держаться
  союзников; вернуться на маршрут; ждать. Старые правила — без «иначе»,
  приоритет 0, поведение «—»: работают как в части 2.
* **Профиль ИИ** получил: приоритеты целей «изолированная», «угрожающая
  базе», «по тегам и типам» (с «предпочитаемыми целями»), «предпочитать
  контроль» (навыки, накладывающие оглушение, обездвиживание, немоту или
  состояние с тегом «control», — первыми), «охранять базу» (центр
  удержания — своя база с наибольшим приоритетом защиты), «вести
  союзников» (союзники ИИ в 6 гексах 3 с бьют цель вожака), «держаться
  союзников», «ломать препятствия», «патрулировать» (шесть точек кольца
  радиуса патруля вокруг позиции; враги вне зоны патруля не замечаются),
  «встреча с защитниками», «альтернативные цели».
* **Встреча с защитниками** (`EncounterDef`, только у врагов на маршруте):
  режим (бегущий к базе, охотник, страж стаи, убийца, танк, поддержка),
  дистанция преследования (−1 — характеристика «дальность преследования»)
  от точки, где враг сошёл с маршрута, уменьшенная «приоритетом базы»
  (×(1 − приоритет); 1 — только блокирующие), время отвлечения, допустимые
  цели, «атаковать движущуюся цель», «сквозь препятствия» (нет — цель, путь
  к которой вдвое длиннее прямой, не преследуется), условие возврата.
  «Бегущий» и «танк» сходят с маршрута только ради того, кто
  **непосредственно угрожает**: стоит рядом и атакует его (это его цель
  или он ударил в последние 3 с); блокирующий обрабатывается раньше, как
  в части 2. Страж стаи сначала бьёт тех, кто атакует его союзников.
* **Возврат на маршрут**: время отвлечения вышло, условие возврата
  выполнено или врагов рядом нет — враг идёт к **ближайшей по стоимости
  пути** точке своего маршрута **впереди**: к оставшимся гексам текущего
  ребра или к узлам, достижимым по графу от него (назад к пройденному
  узлу он не возвращается). Нет пути ни к одной — «маршрут заблокирован» в
  диагностике и отчёте. После возврата новая погоня — не раньше, чем через
  время отвлечения (не меньше 3 с), иначе враг бы бесконечно сходил и
  возвращался к одному защитнику.
* **Альтернативные цели**: база-цель врага уничтожена, или маршрут закрыт
  дольше «база недоступна через» (сценарий, по умолчанию 15 с; «закрыт» —
  нет доступного выхода из узла или нет пути к следующей точке даже без
  учёта юнитов; затор из своих не считается). Список — в профиле, иначе в
  сценарии (по умолчанию: к другой базе, атаковать защитников); берётся
  первая выполнимая: к другой базе (по важности, затем по расстоянию),
  атаковать защитников (идёт к ближайшему), захватить объект (заданный
  или ближайшую цель/контрольную точку/точку взаимодействия), ломать
  ближайшее разрушаемое препятствие, остановиться, отступить к своей базе
  спавна, событие (флаг). Ничего не выполнимо — остановка.
* **События сценария** (`TriggerDef.Event`): начало сценария, завершение
  подготовки, начало и завершение волны (отражена или отменена), появление
  и смерть юнита, достижение цели (объект), уничтожение базы или
  сооружения, активация объекта, контрольная точка маршрута (узел типа
  «контрольная точка»), таймер (с начала боя, повторяемый — каждые N с),
  превышение лимита живых (когда появление впервые начинает ждать),
  выполнение условия (переход «не выполнено → выполнено»), завершение боя;
  плюс наложено состояние, применён навык, сработал пассив. Фильтры:
  объект или ID (база, объект, узел, состояние, навык, пассив; для
  появления и смерти — база спавна юнита или объект сооружения), волна,
  группа, юнит (метка, «tag:», категория, ID шаблона). «Владелец»
  действий — юнит события. Без события — прежнее поведение (условие
  каждый тик). Юниты, расставленные сценарием до начала, событие
  «появление» не порождают (их видно с начала; для них — «начало
  сценария»).
* **Новые действия**: активировать/отключить базу спавна (событие
  сильнее её настройки «активна» и условий), изменить маршрут группы
  (живые враги группы — с ближайшего узла, будущие появления — сразу по
  новому), установить цель (объект — враг уходит с маршрута и идёт к нему;
  метка/тег — атакует их в первую очередь), изменить состояние объекта
  (включить, отключить, разрушить, восстановить здоровье), завершить
  сценарий (победой или поражением, с текстом), записать диагностическое
  событие. «Запустить/остановить волну», «создать юнита», «изменить
  характеристики», «применить эффект», «показать сообщение», «поставить
  на паузу» уже были (запустить волну, отменить волну, призвать юнитов,
  операции каталога, сообщение, автопауза).
* **Защита от циклов**: у триггера — «не чаще, с» и «не более
  срабатываний» (для повторяемых); статическая проверка строит граф
  «действие порождает событие → триггер этого события» (создать юнита →
  появление, запустить волну → начало волны и появление, урон → смерть,
  включить базу → активация и появление, флаг и переменная → «выполнение
  условия» и т. д.); цикл без предела (однократный, частота, максимум) —
  ошибка, с пределом — предупреждение «намеренный цикл». Повторяемый
  таймер, создающий юнитов, без предела срабатываний и без условия —
  предупреждение. В бою событие, вызванное действием, на шаг глубже
  своего; глубже 8 — не обрабатывается (запись в диагностике), больше 2000
  событий за тик — остальные отбрасываются. Циклы «запустить триггер» по
  кругу — ошибка, как в части 2.
* **Отчёт** (`Sim/BattleReport`): наблюдатель подписан на события
  симуляции (`Simulation.Observed`), на результат каждого удара
  (`DamagePipeline.Resolved` — щиты и поглощение) и на конец тика
  (`Simulation.Stepped` — время блокировки маршрутов); симуляция от этого
  не меняется. Показатели — все из ТЗ §10.5; «эффективность лечения» —
  восстановленное здоровье (лечение сверх максимума не считается
  восстановленным) и число лечений; «применения навыков» — запуски
  (`CastReleased`) и попадания (удары с навыком). Для отчёта добавлены
  события: сработал пассив, смена цели ИИ, проблема ИИ (застрял — приказ
  на движение при полном запасе ОД без перемещения 10 с; нет пути; цель
  недостижима — вне досягаемости всех атак и не подойти; маршрут
  заблокирован), конец волны, конец подготовки, контрольная точка.
  Сохраняется в `user://reports/` — JSON и текст.
* **Автобой** (`Sim/AutoBattle`): прогон работает на копии сценария (и
  в редакторе — на копии черновика), то есть данные автора не меняются;
  «только логика» — та же симуляция без отрисовки (тест: отчёт прогона и
  отчёт боя, ведомого кадрами при 1× и 16×, совпадают байт в байт).
  **Пакет**: N прогонов с seed = база + i, параллельно; результаты
  собираются по номеру прогона — сводка не зависит от числа потоков (тест
  1 и 4 потока). Сводка: доля побед, среднее волн, здоровье баз (среднее,
  мин., макс.), частые причины поражения, длительность (среднее, мин.,
  макс., σ), ошибки ИИ, строка на каждый прогон.
* **Скорости**: добавлены ×8 и ×16 (правила, `speedPresets`); при 20
  тиках/с и 60 кадрах ×16 — около 5 тиков за кадр, тики не пропускаются.
  «Без визуальных эффектов» — события только в журнале (ни снарядов, ни
  цифр); «только логика» — остаток боя без отрисовки до конца, остановки
  или лимита, затем отчёт; пошаговый режим — «.» на паузе (часть 1).
* **Остановка на событии** (`Breakpoints`): смерть юнита с тегом (метка,
  тег, категория, ID), срабатывание пассива, блокировка маршрута, враг у
  базы (дошёл или бьёт её), начало волны, конец волны, своё условие (при
  переходе в «выполнено»). В бою — пауза с причиной; в автобое — конец
  прогона «остановка на событии».
* **Интерфейс**: бой — панель «Подготовка к бою» (бюджет, время до
  начала, карточки, «Переставить», «Снять», «Улучшить», «Расставить как в
  тесте», «Начать бой»), зона подсвечена, гекс под мышью — зелёный или
  красный; между волнами — та же панель для перестановки и улучшения;
  меню «Тест ▾»: отчёт прогона, только логика, без визуальных эффектов,
  остановка на событии; «Отчёт» в окне итога боя. TD-сцена — режимы
  «Расстановка и зоны» (клик — гекс зоны; карточка защитника и клик — в
  расстановку по умолчанию, ПКМ — убрать; режим боя; свойства подготовки)
  и «Тестирование» (автотест, пакет N прогонов с seed, потоками и
  пределом длительности, в фоне; результат справа, файлы в
  `user://reports/`). Профили ИИ — те же поля в редакторе профилей
  (приоритет, «Если», «То», «Иначе»).
* **Контент**: 10 профилей группы «Автобой (ч. 4)»: «Страж», «Защитник
  базы», «Стрелок», «Убийца», «Поддержка (автобой)», «Контролёр»,
  «Охотник (по типам)», «Вожак», «Прорыватель», «Патрульный»; сцены
  «Перевал: оборона с расстановкой» (TD с расстановкой: бюджет 30,
  четыре шаблона с лимитами и профилями, улучшение лучницы, зоны у базы
  и на передовом посту, четыре волны с профилями охотника, убийцы,
  прорывателя и стрелка; после второй волны событие открывает южный
  проход — вторую базу спавна) и «Свободная схватка» (свободный бой на
  арене). Профили частей 1–3 не менялись.

### Этап 6. Автоматический уровень и стоимость угрозы

* **Модель силы** (`Content/PowerModel`, без симуляции, только данные):
  две сборки шаблона — базовая (характеристики, навыки) и полная (плюс
  пассивы с ожидаемой долей и правила категорий). Для каждой — эффективное
  здоровье, устойчивый урон в секунду, дальность, мобильность, контроль;
  то же — у эталона. Составляющие **H, D, R, M** — отношение к эталону
  (эталон = 1); **C** — секунд контроля в секунду ÷ «эталон контроля»
  (0,25); **S** — польза союзникам (лечение, щиты, ауры, «за каждого»,
  призыв) — **только** по союзникам контекста.
  * **H**: здоровье, щиты, броня против эталонного удара, уклонение против
    точности эталона, блок, восстановление и самолечение за «длительность
    эталонного боя» (20 с); профиль по основным типам урона проекта
    (пусто — физический наполовину, остальные корневые поровну):
    сопротивление −50 % → ×2, уязвимость +50 % → ×0,667, иммунитет — предел.
  * **D**: по каждому навыку — сила удара × множители всех ударов серии ×
    число попаданий × вероятность попадания × криты × ожидаемое число целей
    области (1 + плотность 0,3 × (гексов − 1)^0,7) ÷ цикл (подготовка +
    восстановление, перезарядка, ОД с их восстановлением, ресурс). Навыки
    делят время с обычной атакой: каждый добавляет только то, что
    превышает урон обычной атаки за время его применения, не чаще
    перезарядки и запаса ресурса; подготовка дольше 0,5 с снижает вклад
    (до −30 %, риск прерывания).
  * **R** — по зонам дальности (порог → множитель: 1, 2 → ×1,2, 4 → ×1,45,
    7 → ×1,7, 10 → ×1,85); **M** — скорость, типы перемещения (полёт,
    прыжок, подкоп), рывки.
  * **C** — оглушение, обездвиживание, немота, прерывание: длительность ×
    шанс × охват ÷ цикл; накопительные состояния — по равновесию притока и
    распада (сколько секунд из каждой цель проводит на пороге), а не
    «каждое применение = полный контроль».
* **Итог**: P = Σ (вес роли × кривая составляющей) для H, D, R+M (веса этих
  четырёх нормированы к 1) + вес C × C + вес S × S, × (1 + «ручной вклад»
  категорий, %), ÷ (1 + контроль эталона). Кривые — линейная, степенная
  (убывающая отдача), предел; зоны дальности — пороговые бонусы. Отчёт —
  строки «Здоровье и защита», «Урон», «Дальность и мобильность»,
  «Пассивные способности» (разница полной и базовой сборки), «Контроль»,
  «Синергия и поддержка», «Ручной вклад категорий», «Итог», у каждой —
  откуда (эфф. здоровье 169 при эталоне 71 и т. п.).
* **Пассивы** — с долей действия: условие «здоровье ниже N %» ≈ N % боя;
  срабатывание — по частоте события (удар, получение урона, убийство) ×
  длительность; аура — по союзникам контекста; условие категории или
  переменной сценария (ночь) — 50 %, если контекст не говорит иначе.
  Категории и теги вклада не дают, только их правила (пассив, модификатор,
  запрет); «ручной вклад» категории (`PowerBonus`, %) — единственный
  способ сделать категорию сильнее напрямую, и он виден отдельной строкой.
* **Роль** (`UnitDef.PowerRole`, «авто» — по составляющим): босс (ранг или
  флаг), поддержка (S в типичной группе ≥ 0,4), контролёр (C ≥ 0,6),
  стрелок (R ≥ 1,3), убийца (M ≥ 1,3 и D ≥ H), танк (H ≥ 1,6 D), иначе
  боец. Веса ролей — в правилах (танк: H 0,55, D 0,3; стрелок: D 0,45,
  R 0,15; поддержка: S 1,2; контролёр: C 0,8…).
* **Шкала уровня** (`LevelScaleDef`): таблица порогов (по умолчанию 1 → 1,
  10 → 4, 30 → 12, 50 → 20, между точками линейно, за последней — по
  наклону последнего отрезка), линейная (шаг силы за уровень), степенная;
  своя шкала роли; отдельная шкала боссов (ранг «босс»). Уровень хранится
  точным (3,15), показывается округлённым — «Уровень 3 (3.15)».
* **Ранг** (`UnitDef.Rank`: обычный, элитный, лидер, босс, свой) уровень не
  меняет; его читают подбор волн (доля элитных), вид и награды; у босса —
  отдельная шкала, если она задана.
* **Эталон** — шаблон из правил (`Power.ReferenceUnit`, во встроенном
  контенте — гоблин), пусто — встроенный (100 здоровья, удар 10). Смена
  эталона пересчитывает всё; в «Правилах боя» при изменении профиля
  «Оценка силы» появляется предупреждение «уровень изменится у N из M
  шаблонов» со списком (было → стало).
* **Калибровка встроенного контента** (эталон — гоблин): гоблин 1,00;
  гоблин-лучник 0,87; волк 1,46; слизь 1,46; волк-вожак 3,15 (в типичной
  группе — 3,96); шаман 3,86 (в группе — 8); страж 5,30; орк-громила 5,52;
  титан (босс) 18,98; у игрока — разведчик 2,12, эльф 2,24, маг 2,99,
  лучница 3,95, жрица 4,67 (в группе — 12), рыцарь 9,56.
* **Контексты**: один (союзников нет), типичная группа (N союзников из
  правил, по умолчанию 3, «такие же, как он»), группа сценария (самая
  большая волна с шаблоном — остальные её враги; шаблон, стоящий в
  сценарии юнитом, — юниты его стороны), против категории (условия «цель —
  категория X» считаются выполненными).
* **«Подогнать под уровень»** (`Content/LevelFit`, `ScalingProfileDef`):
  параметры профиля масштабирования (характеристика, сила навыков,
  сопротивления, лечение, щиты) с весом, мин./макс., «не более чем в N
  раз», шагом, приоритетом и запретом. Новое значение = исходное ×
  f^вес; общий множитель f ищется бисекцией по модели силы — так
  пропорции роли сохраняются (танк растёт в здоровье и броне, убийца — в
  уроне и скорости). Роль закрепляется в результате (иначе подгонка могла
  бы «перевести» шаблон в другую роль и шкалу). Не меняются: категории,
  теги, тип перемещения, ИИ, навыки как набор. Недостижимая цель —
  сообщение с ближайшим уровнем и тем, что разрешить (параметр у
  предела, запрещённый параметр, изменение навыков, добавление
  способностей). Три варианта: базовые характеристики / сила навыков /
  комбинированно. Результат — копия; применить можно как копию шаблона
  (новый ID `<id>_lv<N>`) или как новую версию (черновик заменяется,
  прежняя версия остаётся в истории библиотеки).
* **10 профилей масштабирования** (раздел «Профили масштабирования»):
  равномерное усиление, танк, боец, дальний урон, убийца, поддержка,
  контролёр, босс, мобильный, свой (пустой — заполняет автор). Профиль
  шаблона — его поле, иначе профиль его роли, иначе равномерный.
* **Уровень экземпляра**: у группы волны «уровень» и «уровень до»
  (случайно в диапазоне по seed сцены), у юнита сценария — «уровень».
  Экземпляр получает множители характеристик из «Подогнать под уровень»
  (вариант «характеристики») — шаблон не меняется; кешируется на
  (шаблон, уровень) в бою.
* **Стоимость угрозы** (`Content/ThreatModel`): эталон стоит «стоимость
  угрозы эталона» (2); множители — живучесть (H^0,6), скорость
  прохождения ((скорость/эталон)^0,5), атака защитников, урон по базе,
  обход (полёт ×1,3, подкоп ×1,2, прыжок ×1,1), устойчивость к контролю,
  помощь группе (S в типичной группе), размер, босс ×1,25; округление до
  0,5. В сцене: длина маршрутов ((длина/12)^−0,25 — короткий маршрут
  опаснее), доля узких мест (блокировать проще), эфф. здоровье против
  типов урона защитников сцены, летающий против защитников без
  дальнобойных (×1,5) и с ними (×0,9); на заданном маршруте — то же по
  одному маршруту. Задана автором (`ThreatCost` > 0) — берётся она.
  Подбор волн по бюджету берёт контекстную стоимость, когда в сцене есть
  нарисованный маршрут и хотя бы один защитник; иначе — базовую.
* **«Чрезмерно сильный?»** (`Content/BalanceChecks`, предупреждения в
  проверке контента и в блоке «Оценка силы»): устойчивость к трём и более
  типам урона (эфф. здоровье ≥ 2,5× обычного), самолечение не меньше
  урона двух эталонов, состояние со стаками до 50+, призыв без
  перезарядки, «за каждого» без предела величины и количества, навык
  дешевле обычной атаки и в 4 раза сильнее, «постоянное прерывание»
  (длительность ≥ 0,8 цикла при шансе ≥ 50 %), скорость ≥ 3× эталона,
  устойчивость к контролю ≥ 80 % вместе с мобильностью ≥ 1,5. Ничего не
  запрещается.
* **Интерфейс**: в редакторе шаблона (юниты и враги) справа — блок
  «Оценка силы»: уровень с точным значением, сила и роль, таблица вкладов
  с источниками, эфф. здоровье по типам урона, пассивы с долей, выбор
  контекста, угроза (базовая, на карте, против защитников, на маршруте
  группы — по сцене контекста или первой сцене с шаблоном),
  предупреждения, где используется шаблон (ссылки, группы волн; живые
  ссылки получат изменение, закреплённые `id@N` — нет), сравнение с
  опубликованной версией («уровень 3,15 → в черновике 5,40»), кнопка
  «Подогнать под уровень…». Окно подгонки: целевой уровень, профиль, три
  варианта с таблицей «было → стало», выбор и «Применить» как копию или
  новую версию. Пересчёт — при каждом изменении формы (оценка
  аналитическая, без прогона боя). Карточки библиотеки TD-сцены: «ур. N ·
  угроза X» (угроза — в контексте сцены).
